How It Works

Secret Sharing

Share API keys, tokens, and credentials end-to-end encrypted. The decryption key never reaches the server, so even over ngrok, the middleman can't read your secrets.

  1. Run the share script (or press Ctrl+S in the server TUI)
  2. Type your secret and press Enter
  3. A one-liner is generated and copied to your clipboard
  4. Send the one-liner to the recipient over any channel
  5. Recipient runs it. Secret is decrypted locally and destroyed from memory.
$ curl -sL shellshock.sh/share | bash

The secret is encrypted with AES-256-CBC. The server stores only the ciphertext in memory. The decryption key lives in the one-liner the recipient runs, never on the server. Burns after first retrieval. Auto-expires in 15 minutes.

Remote Debugging

A support engineer runs the server, the customer connects with a one-liner. Every command the engineer sends requires explicit approval on the customer's terminal.

  1. Engineer starts the server and creates a session
  2. Customer runs the connect command
  3. An RSA-2048 handshake verifies the connection
  4. Engineer types commands. Each one is prompted individually on the customer's screen.
  5. Compound commands like ls && rm -rf / are split and prompted per-part
$ curl -sL shellshock.sh/get | bash

Commands are parsed with a character-level finite state machine, not regex. Proxy commands (sudo, env, xargs) are classified by their inner command. Interactive commands (vim, python) give the customer a choice: control it themselves or let the engineer drive.

Security

Encryption
AES-256-CBC (secrets), RSA-2048 OAEP (session handshake)
Storage
Secrets in memory only. Never written to disk, no database, no logs.
Burn after reading
Secret is destroyed after first retrieval
Auto-expiry
Defaults to 15 minutes
Split-token
Auth ID authenticates the request. Decryption key stays client-side.
Bot protection
Requires a custom header. Link preview bots (WhatsApp, Slack, etc.) won't trigger retrieval.
Command safety
Character-level FSM parser. Every command prompted individually. Compound commands split per-part.
Permission rules
Per-session. Approving "git" for one session doesn't carry over.
